# P003-MS04 · Observe task routing and Goal recovery

## Intent

Observe all six specialized kinds and general fallback, an investigation-to-bugfix handoff, and portable Goal exhaustion, explicit extension, recovery, and blocked verification in actual agent sessions.

## Constraints

- Always: keep source fixtures and raw observer artifacts outside the agent's source checkout, use fresh conversations, and preserve unexpected results for review.
- Always: grade actual code, required checks, document evidence, counters, and saved state independently of final claims.
- Never: call structural fixtures agent compliance, change a required gate, supply prior conversation on handoff, or claim a native runtime was activated by portable tests.

## Acceptance

- Given a task prompt and profile, When an agent executes, Then it selects the required next contract, reads the relevant blueprint, and saves it before substantive output changes.
- Given investigation followed by repair, When a fresh session continues, Then evidence and checkpoint guide bugfix selection without precreating future specs or rewriting completed findings.
- Given design, research, runbook, or general work, When completed, Then deliverables contain relevant evidence and application code remains unchanged where required.
- Given a portable Goal, When its budget is consumed or a required gate fails, Then work remains incomplete with truthful stop state; fresh continuation preserves counters and uses only an explicit extension.

## Verify

Run the opt-in routing pilot, inspect JSONL events and snapshots, independently check behavior and original tests, review deliverables against controlled source evidence, and publish actual grades and limits. Keep native integration claims limited to the mapping contract unless a native runtime is actually exercised.
