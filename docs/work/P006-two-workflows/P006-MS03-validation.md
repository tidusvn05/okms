# P006-MS03 · Validation and observed compatibility

## Intent

Keep the checker and opt-in pilots aligned with the two workflows. Prove structural guards with meaningful fixtures and observe agents applying existing-system obligations without a separate profile.

## Constraints

- Always: Accept ordinary five-section plans and plans with both conditional sections, enforce matching shared payloads and versions, and preserve onboarding content guards.
- Always: Record actual agent results, source fingerprints, and unsuccessful criteria; keep historical reports unchanged.
- Never: Treat synthetic contract fixtures as agent compliance, mutate protected application checks, or activate a native runtime.

## Acceptance

- Given either workflow, when checking adoption and repeat setup, then its copied bundle is valid and project-owned content and instructions survive.
- Given a plan, when conditional sections are absent or both present, then the contract is accepted; a partial pair or an unexpected third distribution is rejected.
- Given targeted fresh agent tasks, when Lite repairs existing behavior and Plan-first performs a compatible refactor, then baseline evidence precedes code changes, retained behavior passes independent checks, and Lite stays standalone.
- Given current pilot manifests, when recording source and version, then they identify actual 0.3.0 payloads and retain any failed grade honestly.

## Verify

- Method: Run `.venv/bin/python scripts/check_docs.py`, `.venv/bin/python -m unittest discover -s tests -v`, opt-in Lite and existing-system pilots, source/evidence audits, and `git diff --check`.
- Expected: Required checks and independent behavior pass; observed save order supports the current obligations and reports retain their limits.
- Tests: Add conditional-section and distribution guard fixtures, then observe targeted actual agent sessions; the historical full matrix is not rerun.
